# عقد البيانات v1 — Python 3 دون مكتبات خارجية

## plan.json

الجذر: `schema_version: 1` و`reference_complete` (قيمة منطقية) و`time`، والمصفوفات الخمس `sources`, `outcomes`, `units`, `activities`, `assessments`. مثال قابل للتشغيل: [../assets/example-plan.json](../assets/example-plan.json).

| المجموعة | الحقول |
|---|---|
| sources | `id`, `title`, `locator`, `status`: read_full / read_partial / indexed_only / unavailable |
| outcomes | `id`, `text`, `required` منطقي، `provenance`: verified / proposed / unverified، `source_id` أو null، و`locator` مطلوب للموثق |
| units | `id`, `periods` صحيح غير سالب، `outcome_ids` |
| activities | `id`, `title`, `unit_id`, `outcome_ids` |
| assessments | مثل activities مع `success_criteria` نص أو null |

المعرفات محلية؛ ليست رموز نتاجات رسمية. المصدر «المقروء» لا يثبت صحة الاستخراج تلقائياً. `verified` يحتاج مصدراً مقروءاً وموضعاً، لكن مسؤولية مطابقة النص للمرجع بشرية. `reference_complete` تصريح من المدخل، لا تحقق آلي؛ يوضع true فقط بعد تثبيت قائمة النتاجات المطلوبة كاملة للنطاق.

روابط النشاط/التقويم يجب أن تتضمنها الوحدة الأم، ولا تكرار لمعرف داخل مجموعة أو داخل قائمة روابط. يسمح ربط نتاج بعدة وحدات وبند بعدة نتاجات. الروابط المفقودة تحذير؛ المعرف المجهول خطأ بيانات.

## الزمن: مساران متنافيان

- `basis: gross`: حقلا `weeks` و`periods_per_week` عددان صحيحان موجبان؛ `losses` مصفوفة بنود `reason`, `periods`, `source`. المتاح الصافي = الأسابيع × الحصص − مجموع الخصومات. لا تمرر `net_periods`.
- `basis: net`: `net_periods` صحيح غير سالب يعبّر عن اللقاءات الفعلية بعد الخصومات؛ `losses` فارغة أو محذوفة، ولا حقول أسابيع أو حصص أسبوعية. هذا أنسب للجدول غير المنتظم والأسابيع الجزئية.
- كلاهما يقبل `reserve_periods` صحيحاً غير سالب، افتراضياً 0. السعة التخطيطية = الصافي − الاحتياطي. لا تُعَدّ حصة التقويم ضمن الخصومات إذا خُصصت أيضاً داخل الوحدات.

`units.periods` مجموع كل الحصص المخصصة، بما فيها تقويم/مراجعة إذا كانت جزءاً من الصافي. الأنشطة والتقويم روابط ضمن الحصص نفسها؛ لا تجمع أزمنتها مرة أخرى. الأداة لا تستنتج العطل من التاريخ، ولا تعرف أيام لقاء المبحث، ولا تكشف خصمين متداخلين دلالياً؛ صحح سجل الخصومات يدوياً.

مخرجات `check`: الزمن والعجز، مصفوفة روابط، `structural_link_percent` للمطلوب في المدخل فقط، وتحذيرات. 100% روابط لا يثبت جودة ولا اكتمال المنهاج، حتى لو صرّح المدخل باكتمال المرجع.

## ratings.json

الجذر `schema_version: 1` و`ratings` تضم R1..R7 مرة واحدة. لكل صف: `id`, `status`, `score`, `reason`، و`evidence` قائمة مواضع غير فارغة عند `rated`. الدرجة الصحيحة 0..3، أو null لغير المقدّر. يمكن `weight` أكبر من صفر وحتى 100 لتغيير الوزن وفق اتفاق مسبق؛ الأوزان الافتراضية في `rubric.md`. `critical_failures` قائمة أسباب حاسمة مثبتة، افتراضياً فارغة.

مخرجات `score`: الدرجة المتاحة والتغطية والأوزان وموانع الحكم الكلي. `eligible_for_global_professional_judgment` يسمح **بالتفسير المهني** فقط، ولا يعني النجاح أو الاعتماد. الأدلة والأسباب وسجل المصدر في المدخل جزء من سجل المراجعة ويُحفظ معها؛ لا تستبدلها بالملخص العددي.

## التشغيل

من مجلد المهارة:

```bash
python scripts/plan_checks.py check assets/example-plan.json
python scripts/plan_checks.py score assets/example-ratings.json
python -m unittest discover -s evals -p 'test_*.py' -v
```

مع `--output` حدد ملفاً جديداً في مجلد موجود. المدخل لا يُعدّل. رمز الخروج 0 يعني اكتمال الفحص، وقد تبقى تحذيرات تربوية/زمنية؛ 2 يعني خطأ بيانات/ملف. لا توجد طلبات شبكة أو تثبيت حزم.
